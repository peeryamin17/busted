Before BugSeek looks at anything

BugSeek is a security scanner, and scanners read things. Here is exactly what this one reads, where it lives, and the one case where data leaves this device. Nothing is collected until you say yes.

  • The page you are on — its content and scripts, cookies, and response headers.
  • Linked source maps, when a site ships them.
  • Storage inventories — key names in local and session storage, and JWT claim names. Values are never read or kept.
  • Payment-gateway fingerprints and a map of the third-party services the page talks to.

All of it stays in this browser, in local extension storage. A passive scan sends no requests beyond the page’s own public resources.

Two features run on BugSeek’s backend — the AI swarm and the open-source engines. Those send the target address to our server, which fetches it and has the results analysed (the swarm uses an AI model). BugSeek asks again, separately, before the first of those runs.

Active testing sends real requests to a target. That is a different door: it stays locked behind its own authorisation form and never opens from this agreement.
